## 先看一道题

假设老师布置了 1,024 道两位数乘法。

四个数学高手每人分 256 道，要算一阵子。把题分给一千多个普通同学，每人只算一道，很快就能收卷。

GPU 的思路接近后者：它不追求每个核心都很强，而是放很多简单核心，让大量小计算同时进行。

但 GPU 不是任何时候都更快。如果只有一道很长的连环题，每一步都要用上一步的结果，人多也帮不上忙。

## CPU 和 GPU 的分工不同

CPU 是电脑的主处理器，像几个数学高手。核心少，但每个核心能处理复杂判断，适合操作系统、浏览器、编译器和一串前后依赖的任务。

GPU 是显卡里的处理器，像一屋子普通学生。名字里的 Graphics 来自图形计算，现在也大量用于 AI。单个核心更擅长重复的简单运算，但数量多，适合把同一种操作重复很多遍。

x.com 上，Akshay Pachaar 把 GPU 的工作方式解释为：GPU 不会把一个大计算当成一个任务，而是不断拆成更小的块，直到成千上万个简单操作可以一起跑（[原帖](https://x.com/akshay_pachaar/status/2104557746440086008)）。另一条帖子把 CPU 和 GPU 的差异概括为：CPU 是少量强核心，GPU 是大量简单核心（[原帖](https://x.com/akshay_pachaar/status/2048379111153045663)）。

![CPU 是少量强核心，GPU 是大量简单核心](/images/gpu-cpu-cores.svg)

## GPU 怎么把任务拆开

GPU 不会直接启动一万个互不相干的线程。线程先组成 block，block 再组成 grid。GPU 把 block 分配给 SM（Streaming Multiprocessor）；一个 SM 里有多个 warp scheduler、寄存器文件和 shared memory。

同一个 block 里的线程可以同步，也可以共享 shared memory。不同 block 默认不能直接共享这些数据。

在 NVIDIA 的 GPU 里，32 个线程通常编成一组，叫 warp。warp 是 GPU 调度和执行的基本单位。

一个 warp 里的线程执行同一条指令，只是处理不同的数据。这叫 SIMT：一条指令，多个线程，各自算自己的数。

矩阵乘法很适合这种模式。比如两个 2×2 矩阵相乘，四个结果互不依赖：

```text
C11 = A11 × B11 + A12 × B21
C12 = A11 × B12 + A12 × B22
C21 = A21 × B11 + A22 × B21
C22 = A21 × B12 + A22 × B22
```

每个结果都能交给不同线程。真实模型里的矩阵更大，但道理一样：输出元素越多，越适合并行。

## 矩阵乘法为什么要分块

GPU 的内存不止一种，速度也不同：

![GPU 的内存层次：寄存器、shared memory、L2 和 HBM](/images/gpu-memory-hierarchy.svg)

如果一个线程每次算 C 的一个元素，都直接从 HBM 读 A 和 B 的对应数据，同一块数据会被很多线程反复读。计算单元再快，也会被显存带宽拖住。

所以矩阵乘法通常要分块（tiling）。算输出矩阵的一小块时，先把这一小块需要的 A 行块和 B 列块搬到 shared memory，block 内的线程反复使用，减少 HBM 访问。

访存方式也很重要。一个 warp 的 32 个线程如果读连续地址，硬件可以把它们合并成较少的 memory transaction（访存请求），这叫 memory coalescing。地址跳着读，一次 warp 访存就可能被拆成很多次。

GPU 里还有专门做矩阵乘加的单元。NVIDIA 叫 Tensor Core；它把 `A × B + C` 这类运算做进硬件，吞吐比普通 CUDA core（GPU 的常规计算核心）高很多。但数据布局、精度和 tile 形状要匹配；数据供不上，Tensor Core 也只能等。

## 为什么核多不一定快

厂商标的峰值算力，假设所有计算单元一直满负荷工作。真实程序很少能一直做到。

第一道墙是数据搬运。GPU 计算单元很快，但计算单元旁边的缓存不大，大部分数据要从显存搬过来。Andrej Karpathy 用过一个比喻：计算芯片和显存之间像通过一根吸管搬东西，很多能量都花在搬数据上（[原帖](https://x.com/karpathy/status/1503874225475567620)）。

第二道墙是 occupancy。一个 SM 能同时容纳多少 warp，会影响它能不能用别的 warp 盖住显存等待。如果一个 warp 在等数据，调度器就切到另一个；可运行的 warp 不够，计算单元就会闲着。寄存器或 shared memory 用太多，也会降低 occupancy。

第三道墙是条件分支。一个 warp 里的线程通常要走同一条指令；如果一部分线程走“如果”，另一部分走“否则”，两组不能同时走，只能轮流执行。代码越不规则，GPU 越容易空转。

第四道墙是任务太小。把数据从 CPU 搬到 GPU、启动 GPU 程序都有固定开销；任务太小，省下的时间还不够付这些开销。

## 回到 AI

神经网络里有大量矩阵乘法和向量运算，输出元素之间通常互不依赖，正好适合 GPU 的大量线程。

训练时，batch（一次处理多少请求）大、矩阵大，同一份数据会被大量复用，计算量相对访存量更高，容易变成 compute-bound。这时 Tensor Core 的峰值算力更有用。

推理可以分成两段。prefill 一次处理整段 prompt，矩阵乘法的形状较大，通常还能用满一部分计算单元。decode 每一步只生成一个 token（可以理解为一个字或词片段）；batch 很小的时候，读一遍权重只做很少计算，算术强度低，容易变成 memory-bound。

算术强度可以理解成“每搬 1 byte 数据，能做多少次计算”。算术强度高，瓶颈在计算；算术强度低，瓶颈在显存带宽。

把多个请求拼成一批，可以提高数据复用，让 decode 更接近 compute-bound；代价是 KV cache（上下文缓存）会变大。所以推理优化经常在 batch、显存容量和显存带宽之间做取舍。

## 什么时候不该用 GPU

- 任务必须一步一步做，后一步依赖前一步。
- 代码分支很多，线程很难整齐地执行同一条指令。
- 数据量很小，搬运和启动开销比计算还大。
- 数据复用很低，GPU 大部分时间都在等显存。

GPU 的优势不是“每个核心更强”，而是“同时处理很多相似的小任务”。真正能跑多快，还要看数据能不能及时送到、warp 够不够多、代码是否整齐。
