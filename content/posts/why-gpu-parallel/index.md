## 先看一道题

假设老师布置了 1,024 道两位数乘法。

班里有四个数学高手，每人分 256 道，要算一阵子。换成一千个普通同学，每人只算一道，很快就能收卷。

GPU 的思路接近后者：它不追求每个核心都很强，而是放很多简单核心，让大量小计算同时进行。

但 GPU 不是任何时候都更快。如果只有一道很长的连环题，每一步都要用上一步的结果，人多也帮不上忙。

## CPU 和 GPU 的分工不同

CPU 是电脑的主处理器，像几个数学高手。核心少，但每个核心能处理复杂判断，适合操作系统、浏览器、编译器和一串前后依赖的任务。

GPU 是显卡里的处理器，像一屋子普通学生。名字里的 Graphics 来自图形计算，现在也大量用于 AI。单个核心更擅长重复的简单运算，但数量多，适合把同一种操作重复很多遍。

x.com 上，Akshay Pachaar 把 GPU 的工作方式解释为：GPU 不会把一个大计算当成一个任务，而是不断拆成更小的块，直到成千上万个简单操作可以一起跑（[原帖](https://x.com/akshay_pachaar/status/2104557746440086008)）。另一条帖子把 CPU 和 GPU 的差异概括为：CPU 是少量强核心，GPU 是大量简单核心（[原帖](https://x.com/akshay_pachaar/status/2048379111153045663)）。

## GPU 怎么把任务拆开

GPU 把线程按组管理。可以把线程理解成一个个小工人；在 NVIDIA 的 GPU 里，通常 32 个小工人编成一组，叫 warp。

一个 warp 里的线程执行同一条指令，只是处理不同的数据。这叫 SIMT：一条指令，多个线程，各自算自己的数。

矩阵乘法很适合这种模式。比如两个 2×2 矩阵相乘，四个结果互不依赖：

```text
C11 = A11 × B11 + A12 × B21
C12 = A11 × B12 + A12 × B22
C21 = A21 × B11 + A22 × B21
C22 = A21 × B12 + A22 × B22
```

每个结果都能交给不同线程。真实模型里的矩阵更大，但道理一样：输出元素越多，越适合并行。

## 为什么核多不一定快

第一道墙是数据搬运。GPU 计算单元很快，但计算单元旁边的缓存不大，大部分数据要从显存搬过来。Andrej Karpathy 用过一个比喻：计算芯片和显存之间像通过一根吸管搬东西，很多能量都花在搬数据上（[原帖](https://x.com/karpathy/status/1503874225475567620)）。

第二道墙是条件分支。一个 warp 里的线程通常要走同一条指令；如果一部分线程走“如果”，另一部分走“否则”，两组不能同时走，只能轮流执行。代码越不规则，GPU 越容易空转。

第三道墙是任务太小。把数据从 CPU 搬到 GPU、启动 GPU 程序都有固定开销；任务太小，省下的时间还不够付这些开销。

## 回到 AI

神经网络里有大量矩阵乘法和向量运算，输出元素之间通常互不依赖，正好适合 GPU 的大量线程。

但生成文字时，GPU 经常不是算不动，而是在等数据。每生成一个 token（可以理解为一个字或词片段），都要读大量权重和上下文缓存；显存带宽就是单位时间能搬多少数据。数据供不上，计算单元就会闲着。

这也是为什么推理不只比算力，还要看显存带宽和容量。

## 什么时候不该用 GPU

- 任务必须一步一步做，后一步依赖前一步。
- 代码分支很多，线程很难整齐地执行同一条指令。
- 数据量很小，搬运和启动开销比计算还大。

GPU 的优势不是“每个核心更强”，而是“同时处理很多相似的小任务”。理解这一点，就能判断一个任务该不该交给 GPU。
